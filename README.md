# Supplier Scout

Рабочий прототип для поиска и сравнения поставщиков продуктов для HoReCa. В демо — кофе в зернах и чай, доставка в Екатеринбург и Москву. Поиск идёт по проверенному каталогу, не по всему интернету.

## Что умеет

- показывает 10 реальных поставщиков с официальными источниками;
- выбирает категорию и город; чай подтверждён у 4 компаний;
- фильтрует по подтверждённой доставке, опубликованной цене и минимальному заказу;
- различает объём за заказ и за месяц; не переводит денежный минимум в килограммы;
- объясняет рейтинг до отдельных критериев и подтверждающих фрагментов;
- сравнивает до трёх поставщиков и формирует текст запроса коммерческого предложения;
- экспортирует shortlist в CSV;
- продолжает работать из статического снимка, если API недоступен.
- сообщает об ошибке загрузки снимка и позволяет повторить запрос;
- показывает текст запроса для ручного копирования, если буфер обмена недоступен.

Официальные страницы проверены 21 сентября 2026 года; прямые контакты есть у всех 10 компаний. Дата означает проверку публикации, не подтверждение коммерческого предложения менеджером. У Frumentum на сайте расходятся минимумы: число исключено из подбора до уточнения. Цена «от» служит ориентиром, а не сравнением одинаковых товаров. Опубликованные документы не заменяют проверку применимости и срока действия.

## Модель и ограничения

`data/suppliers.json` — единственный редактируемый источник; сборка копирует его в `public/suppliers.json`. Контакты и источники хранятся на уровне компании, условия — в `offers` отдельно для каждой категории. `delivery_regions` различает подтверждённую доставку (`true`), отказ (`false`) и неизвестность (`null`). Неизвестные регионы видны с предупреждением; фильтр «Доставка подтверждена» исключает их.

Скоринг `horeca-v3`: категория 30, доставка 25, подходящий минимум 15, источник до 15, свежесть до 10, опубликованная цена 5. Баллы за минимум начисляются только при известном количестве в кг и совпадающем периоде. Условия в рублях и неизвестные условия дают 0, а не считаются подходящими. Это демонстрационные веса, не оценка качества поставщика. Общие тестовые случаи в `data/scoring-cases.json` проверяют одинаковые правила Python и TypeScript.

API `/api/v1/catalog` отдаёт полный каталог для интерфейса. `/api/v1/suppliers`, карточка и `/api/v1/compare` принимают одинаковые параметры: `category`, `region`, `requested_kg`, `requested_period`. Сравнение возвращает всех лидеров по баллам в `leading_ids`, не назначая произвольного победителя при равенстве.

## Быстрый старт

```powershell
npm.cmd install
npm.cmd run dev
```

Frontend откроется на `http://localhost:5173`. Без backend он автоматически использует снимок. На GitHub Pages без `VITE_API_BASE_URL` снимок загружается напрямую; локальный dev сначала пробует API через proxy.

Backend:

```powershell
cd backend
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload
```

API: `http://127.0.0.1:8000/docs`.

Для подключения публичного frontend к размещённому API задайте repository variable `VITE_API_BASE_URL` (например, URL сервиса Render без завершающего `/`). Допустимые CORS-origin backend принимает из `SUPPLIER_SCOUT_CORS_ORIGINS` через запятую.

## Проверки

```powershell
npm.cmd test
npm.cmd run build
cd backend
python -m pytest
```

E2E-проверка обоих интерфейсов требует соседнюю папку `../portfolio`, зависимости и production-сборку обоих проектов. Она сама запускает preview на портах 4173/4174 и использует установленный Chrome/Edge:

```powershell
npm.cmd run test:e2e
```

На Linux или при нестандартном расположении браузера задайте `CHROME_PATH`.

## Почему такой формат

Визуальный референс — [goulash.tech](https://goulash.tech/): графитовая шапка, бирюзовые акценты и шрифт Onest. Каталог и сравнение остаются светлыми для чтения таблиц. Шрифт с кириллицей включён в сборку, основной текст — 18 px, подписи — от 14 px. Предусмотрено отключение анимаций через `prefers-reduced-motion`. Это самостоятельное тестовое задание, не официальный продукт Goulash.

Статический fallback делает ссылку на прототип надёжной для просмотра рекрутером. FastAPI + SQLite показывают рабочий API и модель данных, не превращая тестовое задание в инфраструктурный проект. Скоринг намеренно детерминирован: его можно проверить, обсудить с закупщиками и заменить после пилота.

## Как развивать

1. Интервью с закупщиками и фиксация реальных весов критериев.
2. Полуавтоматическое извлечение условий из страниц с обязательным human review.
3. История изменений и напоминания о повторной проверке.
4. Документы/сертификаты, тендерный контур и интеграция с ERP.
